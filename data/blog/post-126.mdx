10 月 17 日，DeepSeek 更新了 V4.1-Flash-1017。比起基准跑分，官方这次给出的几个承诺更吸引我：更快完成任务、更低的任务成本，以及“许愿式编程”。

为了看看实际效果，我用 DeepSeek Harness 桌面端（0.2.1-rc.2）跑了五个真实任务：把 PDF 简历改成网站、做 PPT、做 Agent 科普动画视频、开发 DSH 插件，再加一篇从调研、开发到成文的 Person Agent 教程。

先说结论：**它的指令遵循确实变好了，交代的事基本都能做出成品。但宣传里那种“花更少的钱，更快拿到更好结果”的爽感，我并没有体会到。尤其是面对复杂任务，执行链路依然很长，中间还得我频繁救场。而且花费更长的时间**

下面除了看最终成品，我更想聊聊这十几个小时里，我和它之间到底经历了什么。

## 官方说的“帕累托改进”，能直接当真吗？

按照[官方发布说明](https://api-docs.deepseek.com/zh-cn/news/news261017/)，这次更新缩短了任务运行时间与输出长度，并针对 DeepSeek Harness（官方建议升级到 **0.2.1-rc.1 及以上**）、CodeBuddy、WorkBuddy 等框架做了专门优化。在[官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)中，DeepSWE v1.1 的分数也从上一版的 74.2 涨到了 77.0。

官方这次用了一个很学术的词：**性能与费用的帕累托改进**。简单说，就是在同等甚至更低的成本下，把活干得更好。

不过看官方数据得留个心眼。官方成本图里标注了测试环境是 mini-swe-v2 框架下的 DeepSWE 基准。跑分环境里的**单任务成本**，显然没法直接当做成我们日常做个完整网站、渲染一段视频或者写个插件。

所以让我来实测看看效果

## 顺便看一眼新服务：Search 和 Fetch

这次更新还同步开放了网页搜索（Search）和网页抓取（Fetch）接口。对于需要先查资料再干活的 Agent 任务来说，这算是补齐了关键拼图。

这两个接口官方定价都是 **5 元／千次**。按照[官方说明](https://api-docs.deepseek.com/zh-cn/news/news261017/)，目前在 Harness 等场景里通过服务端调用它们暂时免费，但从 **2026 年 11 月 1 日 00:00（北京时间）** 起就要正式按次计费了。

这也意味着，以后使用 DeepSeek，不能光盯着模型 Token，还得留神它在后台调了多少次外部搜索和抓取。

## 实测

![image-20261017221421250](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/image-20261017221421250.png)

这是测试前的余额，让我们看看这五个任务这点钱够不够

### 1. Agent 友好的在线简历

![image-20261018202312208](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/image-20261018202312208.png)第一个任务很明确：给它一份现有的 PDF 简历，做成网页版；核心数据得抽离成 Markdown，方便以后让 Agent 针对不同岗位动态调整；技术栈指定用 Cloudflare 刚发布的 Void，最后直接部署上线。

不得不说，它对需求的理解很到位。最终交付物里，Markdown 数据源、网页前端、Agent 工作台、定制版本、校验脚本和公开接口一应俱全，也成功推到了 Cloudflare 上。**它把“数据与展示分离”的架构做得很好**，但过程实在是曲折漫长。

翻看日志，第一轮耗时 39 分钟。等待过程中它半天没动静，结果卡在 Cloudflare 登录和部署环节：授权后写入 macOS 钥匙串失败（不断重试），紧接着又撞上运行环境和网络问题。此外它在没跟我确认基础版式之前，自己写了编辑界面和暗色模式等附加功能，但是这也是我提示词没有写得很严格的原因。我用 Codex 一样的提示词也出现一样的问题，但是人家是否能做就做完了

我觉得这是一个真实的实用场景，但它做得效果不是很好，而且花了很多时间和需要我不断推进。

### 2. 制作 PPT

![img](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/image-20261018203045179.png)

第二个任务是做一份介绍 DeepSeek V4.1 Flash 更新的 PPT，要求浅色背景、风格简洁干净。只用了 5 分钟，它就完成了，做出的效果还真不错，就是和所有AI一样，喜欢写一些小字，不需要的内容。但是内容涵盖了模型更新、跑分对比、官方案例、搜索接口和升级建议等等，这说明它并非干啥都慢。**碰到这种目标清晰、素材现成、交付格式固定的标准任务，它的动作还是相当利索的。** 当然，这个 PPT离直接拿去正式场合演讲肯定还有差距，但作为初稿已经很不错了～

### 3. 科普视频制作

做视频是 Opus 5.5 目前非常擅长的能力。我的需求是：用 JavaScript 做一个动画视频，让观众看完能明白“一个 Agent 是怎么被制作出来的”。它花了  11分钟做出了初版，总结就是很丑，我就不放出来了

![image-20261018204648874](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/image-20261018204648874.png)

然后我就让它优化：画面做减法，只留核心元素；先出文案脚本再配音；把深色背景全换成浅色；配音换个好听的男声。

在执行这些具体修改时，它表现得很听话，画面风格、脚本、配音和渲染流程都照办了。**只要把指令拆得足够细，它完全能跟上节奏。**

但等新视频渲染出来，我发现了一个更致命的问题，就是内容跑题了，我的需求是这个视频让一个用户看完之后，他就知道一个 Agent 是如何被制作出来的。但是它讲的全是“Agent 由哪几部分组成”（模型、工具、记忆等概念拆解），而我要的是“动手制作 Agent 的步骤指南”。被我点破之后，它把脚本推倒重来，改成“写说明、选模型、接工具、加记忆、装循环、测试、发布”的实操流程，接着重新配音、重新渲染，反正多次调整了 1小时后，它的成果如下：

![CleanShot 2026-10-18 at 21.00.57](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/CleanShot%202026-10-18%20at%2021.00.57.gif)

这是最终版，效果还是不好，做视频还是老老实实使用 Opus 5.5 。这个任务让我看到了它真的做比较困难的任务的时候就是会花费超过时间，并且可能会走错路，综合下来，花费了更多的Token，而且花费了更多的时间。

### 4. DSH 插件开发

![CleanShot 2026-10-18 at 20.57.49](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/CleanShot%202026-10-18%20at%2020.57.49.gif)

这个任务源于我的一个真实痛点：每次开启一个新任务，我都需要手动调整它的思考程度。因为这个思考程度对结果影响比较大，对任务完成时间的影响也比较大。 

我就想能不能用 Cloudflare Clef 先判断当前 Prompt 的难度，再自动切换 DeepSeek 的推理等级？简单问题少费点脑子，复杂任务再开深度思考。

吸取了前面的教训，我一上来就立了规矩：**先调研可行性，给我看方案，我点头了再写代码。**这次它很守规矩，老老实实停下来等我确认方案。从最终交付的代码看，它的工程能力确实顶得住：它理解了 DSH 的插件机制，也调通了外部 Clef 接口，还完成了前后端联调的工作，实现了自动调整思考程度的能力。

但是我自己使用的过程中发现它还存在超时预算太短导致判断失败，并没有提醒的问题，这体现了它面前在自我验证方面应该还是存在一些问题的

### 5. 写作能力实测

最后一个任务是个综合性的任务：全网搜索 Person Agent 资料，整理 GitHub 相关项目，基于 Pi Durable 手搓一个自己的 Person Agent 并部署到 Cloudflare，最后打包源码，再写一篇面向普通人的保姆级教程。

![CleanShot 2026-10-18 at 21.04.10@2x](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/CleanShot%202026-10-18%20at%2021.04.10@2x.png)

这个任务跑了18 分钟，顺利拿到了工程源码，以及 Markdown、HTML、PDF 三种格式的教程。

文章内容从概念科普、架构图解、环境准备，一路讲到改配置、部署上线和日常排障，中间还穿插了不少生活化的比喻来降低阅读门槛。但是我相信很多人看不下去，因为太无聊了，**它确实是个搜集资料、搭文章框架的高手，但写出来的东西还不能直接当成免检的终稿发布。** 

## 使用后感受

![CleanShot 2026-10-18 at 21.21.05@2x](https://pub-0d530dc48245462d8f3734870a46cd58.r2.dev/typora/CleanShot%202026-10-18%20at%2021.21.05@2x.png)

这次测试没有拉账单明细，但跑完这五个任务，我的真实体感很明确：**为了拿到这些结果，我搭进去的时间、Token 和精力，超出了官方宣传给我的心理预期。**

衡量一个 Agent 贵不贵、好不好用，单看接口定价和跑分是没有意义的。把它放在真实场景看看它能不能解决问题，省心省时间。很显然 DeepSeek 这次更新后还是做不到

总结下来，这次体验里有三个最扎眼的痛点：

- 不知道在思考什么，反正干活很慢
- 需求理解水平有待提高
- 制作视频完全不可用

我也没有太多时间细致测试，这是我的大体感受，我真的很喜欢 DeepSeek，希望它能干活，但是每次花费 1～2 天的时间，最后的结论都是：“还不行”

## 总结

如果单纯问“DeepSeek 新版本能不能干活”，我的回答很肯定：**能，而且能啃下有一定复杂度的工程任务。**

无论是数据分离的简历站、PPT、动画视频，还是带 UI 状态的插件，它都实打实地交出了可用产物；对浅色风格、特定技术栈、UI 交互细节等明确要求，执行得也很到位。

但如果问：**它有没有让我花更少的钱、更快拿到更好的结果？有没有实现“许个愿就不用管”？**

至少在这轮高强度实测里，还没有。

现在的它，更像一个态度极好、手脚勤快、愿意反复改稿的助手。你依然需要帮它把控大方向、验收半成品、搞定权限卡点，并在它钻牛角尖的时候及时把它拽回来。反正就是不聪明吧～

**毕竟对真正在用 AI 干活的人来说，把一件事从头到尾做成、总共花了多少钱、耗了多少时间、费了多少神，才是衡量性价比的唯一标准。** 这次更新让我看到了不错的指令遵循能力，但真正的“省钱省心”和“许愿式编程”，还得再等等
